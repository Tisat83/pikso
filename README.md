# Pikso — онлайн-доска для совместного рисования

Лёгкий реального времени whiteboard: приватные комнаты, модераторы, экспорт PNG/PDF и локальная персистенция (без БД).

## Стек
- **Node.js + Express + Socket.IO**
- Клиент: **HTML/JS/CSS** (без фреймворков)
- Персистенция: `data/rooms.json`

---

## Основные возможности
- Рисование в реальном времени (стриминг штриха: begin → progress → finish)
- Видимые курсоры участников, имена/цвета
- Приватные страницы (уникальные ссылки), публичная демо-страница
- Онлайн-список (иконка «глаз» + счётчик), всплывающий список участников
- **Модерация:** владелец комнаты — модератор автоматически; другие — по паролю
- **Ластик по пересечению** (стирает при пересечении линии)
- **Undo / Redo** (персональные стеки для каждого клиента)
- Экспорт **PNG / PDF**, копирование ссылки (share)
- «Мои страницы»: список собственных комнат + удаление с подтверждением
- Персистенция комнат и штрихов в файл (`rooms.json`)

## Персистенция
- Файл: `data/rooms.json` (создаётся автоматически).
- Сохраняется: `ownerClientId`, `strokes[]`, `moderators[]`, `createdAt`.
- Загружается на старте. Лог: `[persist] loaded N rooms`.

## Комнаты, владелец, модераторы
- **Создание комнаты** (`POST /api/rooms`): владелец = текущий `clientId` → **сразу модератор**.
- **Владелец** при входе в свою комнату становится модератором **автоматически** (без пароля).
- **Другие** пользователи могут стать модераторами по **паролю** (`MOD_PASSWORD`).

### Права модератора
- Стирание чужих штрихов (ластик и «Удалить штрих»)
- Очистка холста
- Удаление комнаты (если владелец или модератор — разрешено REST-эндпоинтом)

---

## API (минимальный)
### `POST /api/rooms`
Создаёт комнату.
```json
Request: { "clientId": "..." }   // владелец
Response: { "roomId": "r-xxxx" }
```

### `GET /api/rooms?ownerClientId=...`
Возвращает комнаты, созданные данным владельцем.
```json
{ "rooms": [ { "roomId": "r-..." }, ... ] }
```

### `DELETE /api/rooms/:id`
Удаляет комнату (владелец или модератор).
```json
Request: { "clientId": "..." }
Response: { "ok": true }
```

## Ключевые события Socket.IO
Клиент → Сервер:
- `join` `{ roomId, clientId }`
- `presence` `{ roomId, name, color }`
- `stroke-begin` / `stroke-progress` / `stroke` `{ roomId, ... }`
- `cursor` `{ roomId, x, y, visible, name, color }`
- `delete-stroke` `{ roomId, id }`
- `undo` / `redo` `(roomId)`
- `clear` `(roomId)`
- `request-moderator` `{ roomId, code, value:true|false }`

Сервер → Клиент:
- `init` `{ strokes, ownerClientId, moderators, members }`
- `members` `[ { clientId, name, color }, ... ]`
- `moderators` `[ { clientId, name, color }, ... ]`
- `stroke-begin` / `stroke-progress` / `stroke` / `stroke-finish`
- `stroke-deleted` / `stroke-restored`
- `cleared`
- `moderator-set` `{ value:true|false }`
- `delete-denied` / `clear-denied`

---

## Undo / Redo (как устроено)
- Для каждого клиента хранится отдельный стек `redoStacks[clientId]` (в памяти; не пишется в файл).
- `undo`:
  - находит последний штрих пользователя (или любой — если модератор),
  - удаляет его из общего массива `strokes`,
  - кладёт штрих в `redoStacks[clientId]`,
  - шлёт `stroke-deleted` всем.
- `redo`:
  - берёт штрих из вершины `redoStacks[clientId]`,
  - возвращает в `strokes`,
  - шлёт `stroke-restored` всем.
- Любой **новый** штрих **очищает** redo-стек текущего пользователя.

## Частые вопросы
- **Ввёл пароль — тост «Вы стали модератором», но бейджа нет.**  
  Клиент сразу синхронизирует `moderatorsSet` и вызывает `updateMembers()`. Если не видно — обнови страницу `Ctrl+F5` и проверь консоль ошибок.
- **Старые комнаты не считают меня владельцем.**  
  Комнаты, созданные до включения персистенции, могли не иметь `ownerClientId`. Временное решение — стать модератором по паролю и пересоздать. При необходимости добавим `POST /api/rooms/:id/claim`.
- **Не скачивается PDF большого холста.**  
  Используется «видовой экспорт» либо ограничение масштаба/страниц. Оптимизация включена (в т.ч. «Показать весь рисунок»).
